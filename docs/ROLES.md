# Роли и права GetSite OS

Источник истины — объект `ROLES` в `lib/auth.js`. Клиент получает разрешённые
разделы через `/api/auth/me`; сервер отдельно проверяет каждое действие.
Скрытие кнопки в интерфейсе не считается защитой.

В документации ниже используются пользовательские названия. В API им
соответствуют внутренние labels: «Деньги» → `Оплаты и расходы`,
«Себестоимость» → `Unit Economics`, «Отчёты» → `Аналитика`,
«Готовность системы» → `Готовность`.

## Основатель (`founder`)

Видит все разделы и может выполнять все зарегистрированные действия.

Основные полномочия:

- управление пользователями, ролями и паролями;
- настройки компании и экономики;
- заявки, клиенты, сметы, проекты и финансы;
- прайс, себестоимость, аналитика и аудит;
- управление задачами, план/фактом и сдачей проекта.

Нельзя отключить собственный аккаунт. При смене собственного пароля требуется
текущий пароль. Сброс пароля другого пользователя доступен основателю.

## Менеджер продаж (`sales_manager`)

Разделы:

- Главная
- Заявки
- Клиенты
- Сметы
- Проекты
- Деньги
- Прайс
- Скрипты продаж
- История

Разрешено:

- создавать и вести заявки, квалифицировать лиды;
- создавать и обновлять клиентов;
- создавать, согласовывать и конвертировать сметы;
- создавать и обновлять проекты;
- создавать и отмечать оплаты;
- создавать и обновлять расходы;
- изменять клиентскую цену существующей услуги;
- вести скрипты продаж.

Запрещено:

- системные настройки и роли;
- отдельная страница себестоимости;
- изменение внутренних часов и себестоимости услуги;
- произвольные административные действия.

## Дизайнер (`designer`)

Разделы:

- Главная
- Проекты
- Команда и сроки
- История

Разрешено:

- создавать, обновлять и удалять задачи;
- обновлять доступный проект;
- вести план/факт;
- заполнять чек-лист сдачи;
- завершать onboarding.

Доступ ограничен проектами, где дизайнер назначен ответственным или исполнителем
задачи. Если сервер не может определить проект для изменяющего действия, запрос
отклоняется. Клиенты, лиды и финансовые данные дизайнеру не выдаются.

## Изменение модели доступа

1. Изменить `ROLES` и server-side проверки в `lib/auth.js` / `server.js`.
2. Проверить фильтрацию данных в `filterStateForUser`.
3. Не добавлять отдельные hardcoded роли в UI: навигация использует sections
   из `/api/auth/me`.
4. Обновить этот документ и `State.md`.
5. Запустить `npm test` и `npm run qa:all`.

Новая роль не должна наследовать права через неизвестное значение:
`normalizeRole` обязан возвращать только зарегистрированный role id.
